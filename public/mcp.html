ABRAXAS PUBLISHER · MCP

Controla Publisher desde un agente de IA.

El MCP conecta ChatGPT, Codex, Claude u otro cliente compatible con el mismo motor real de ABRAXAS Publisher. Puede leer contenido, revisar estados, calendarizar, registrar correcciones, preparar publicaciones y ejecutar herramientas sin crear una base paralela.

Cómo funciona

La idea es simple: el agente no toca archivos al azar. Llama herramientas MCP que pasan por el bridge Rust y el backend real de Publisher.

ChatGPT / Codex / Claude
        ↓ MCP stdio
mcp/server.mjs
        ↓
publisher_mcp_bridge (Rust)
        ↓
Backend de ABRAXAS Publisher
        ↓
SQLite · scanner · ffmpeg · publishing

Una sola fuente

El MCP usa el mismo workspace y la misma SQLite del Desktop.

Sin servidor abierto

Funciona por stdio local. No publica tu base de datos en un puerto HTTP.

Con confirmaciones

Las acciones sensibles exigen confirmación explícita.

Instalación paso a paso

1

Actualiza Publisher

Usa el script de reparación/actualización incluido en el repo. Compila la app, instala el MCP y conserva backups.

2

Instala el MCP

cd ~/Developer/abraxas-publisher
npm run mcp:install

El instalador deja una copia estable en ~/.local/share/abraxas-publisher-mcp.

3

Configura tu cliente MCP

{
  "mcpServers": {
    "abraxas-publisher": {
      "command": "node",
      "args": [
        "/Users/TU_USUARIO/.local/share/abraxas-publisher-mcp/server.mjs"
      ],
      "env": {
        "ABRAXAS_PUBLISHER_MCP_BRIDGE": "/Users/TU_USUARIO/.local/share/abraxas-publisher-mcp/publisher_mcp_bridge"
      }
    }
  }
}
4

Prueba la conexión

Pide al agente: “Usa Publisher MCP y ejecuta el doctor. No cambies nada.”

Casos de uso

1. Revisión diaria

Prompt:

Revisa Publisher y dime qué necesita atención hoy.
Separa: con corrección, listo por programar, errores técnicos y trabajos manuales.
No cambies nada.

Lectura → diagnóstico → resumen.

2. Dejar una corrección

Abre la ficha “Reel criterio de decisión”.
Deja la nota: “Cambiar portada por la versión aprobada”.
Márcala CON_CORRECCION y verifica el resultado.

Buscar ficha → leer → guardar corrección → releer para verificar.

3. Calendarizar un contenido

Programa el Reel X para Instagram el 8 de octubre a las 5:00 PM.
No lo marques como programación remota.

Encontrar target → actualizar fecha → verificar calendario.

4. Preparar una publicación

Prepara el contenido X para Instagram con la cuenta JOC.
Haz preflight primero y dime si será AUTO, MANUAL o EXTERNAL.
No encoles nada hasta que te confirme.

Ficha → cuenta → preflight → explicación → confirmación → queue.

5. Registrar algo programado fuera

Ya programé esta pieza en Meta Business Suite para mañana a las 6 PM.
Regístralo en Publisher.

Confirmar target/fecha/método → registrar SCHEDULED_EXTERNAL.

6. Importar una carpeta local

Analiza esta carpeta de contenido y dime primero qué importaría.
Después de mostrarme conflictos o duplicados, pregúntame antes de importar.

Preview/dry-run → conflictos → confirmación → importación.

7. Diagnóstico técnico

Ejecuta el doctor de Publisher y revisa SQLite, ffmpeg, ffprobe y estado del workspace.
No cambies datos.

8. Preparar una semana

Revisa los contenidos de JOC de esta semana.
Agrúpalos por estado, detecta los que faltan calendarizar y propón un plan.
No escribas nada todavía.

Criterios que debe seguir el agente

  1. Leer antes de escribir.
  2. Verificar después de escribir.
  3. No inventar IDs de contenido, target o cuenta.
  4. Si hay varias coincidencias, mostrar las opciones.
  5. Usar preflight antes de encolar publicaciones.
  6. Una fecha local no equivale a programación remota.
  7. PROGRAMADO editorial no equivale a SCHEDULED_REMOTE.
  8. MANUAL_REQUIRED no es un error.
  9. No borrar workspace/cuentas sin confirmación.
  10. No guardar passwords, service-role keys ni tokens OAuth.
  11. En lotes grandes, hacer dry-run/preflight primero.
  12. Después de importar o refrescar, releer y verificar.
Acciones sensibles: importar local, eliminar cuentas, encolar publicaciones, registrar programación externa y limpiar workspace exigen confirm: true.

Problemas comunes

El cliente no ve Publisher MCP

Comprueba que la configuración apunte a ~/.local/share/abraxas-publisher-mcp/server.mjs y al bridge de la misma carpeta. Reinicia el cliente MCP después de cambiar su configuración.

El self-test falla

cd ~/Developer/abraxas-publisher
npm run mcp:test

No encuentra ffmpeg

Ejecuta publisher_doctor. En Mac con Homebrew normalmente debe estar en /opt/homebrew/bin/ffmpeg.

Drive pide login

Es normal. Completa OAuth dentro de Publisher. El MCP no debe almacenar esa sesión por su cuenta.

Quiero publicar automáticamente

Primero usa publisher_preflight. Si el provider/API no está realmente disponible, el resultado debe permanecer MANUAL/EXTERNAL, nunca fingir éxito remoto.

Modelo mental rápido

“Dime qué hay”       → tools de lectura
“Cambia esto”        → leer → escribir → verificar
“Publícalo”          → preflight → confirmar → encolar
“Ya lo publiqué”     → registrar externo
“Borra / limpia”     → confirmación explícita

El objetivo del MCP no es saltarse el criterio editorial. Es permitir que un agente opere Publisher con las mismas reglas, estados y motor que la app.
